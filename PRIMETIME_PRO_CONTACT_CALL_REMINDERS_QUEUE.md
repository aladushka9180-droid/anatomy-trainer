# PrimeTime Pro: контакт, звонок и напоминания

## Цель и состояние

Последовательно проверить связь системного контакта с карточкой клиента и записью, выполнимый сценарий входящего звонка, напоминание мастеру и отдельное сообщение клиенту. Владелец направления — эта задача; общие Pro-файлы и выпуск принадлежат одному согласованному владельцу релиза.

### 1. Системный контакт → карточка → запись

- Веб/PWA v978 уже опубликован: `d28259e7` сопоставляет выбранный контакт с CRM по нормализованному номеру и имени. Если имя отличается, оно не подменяется молча: форма показывает совпадающие карточки по номеру для явного выбора. Новый номер остаётся черновиком до штатного подтверждения записи. Карточка и история в Pro группируются по номеру.
- Проверено: `client-phone-autofill-v515-test.mjs` с синтетическими контактами; JS syntax. Выпуск v978 и совпадение живых ресурсов с релизом описаны в `MILESTONE.md`. На живой форме проверено открытие без сохранения записи. Системный выбор контакта в установленном Android и полный путь до подтверждённой записи не проверены и требуют отдельного разрешения на работу с физическим устройством/реальными данными.
- Старый кандидат `2046f02a` не интегрировать: он автоматически заменяет отличающееся имя по одному номеру и противоречит проверенному контракту v978.

### 2. Входящий звонок → карточка и история

- Веб/PWA не получает входящие телефонные события. Имеющаяся Android-оболочка только по нажатию пользователя и после разрешения `READ_CALL_LOG` предлагает выбрать номер из недавних входящих; автоматического определения во время звонка в ней нет.
- Следующий безопасный вариант: после явного выбора номера найти клиента по нормализованному телефону и открыть карточку с историей, не сохраняя запись автоматически. Автоматический показ при звонке требует отдельной нативной реализации, системной роли/разрешений, решения пользователя и проверки на физическом устройстве.
- Статус: граница подтверждена кодом; реализация перехода не начата. Ожидается один продуктовый выбор: открывать карточку после ручного выбора номера или автоматически во время входящего звонка. До ответа общие Pro-файлы не менять.

### 3. Напоминание мастеру

- Сначала проверить действующий контракт локальных/system и серверных уведомлений, время, отмену и идемпотентность. Проверять на синтетических будущей, прошлой и отменённой записях и при сбое связи. Ожидающую офлайн-запись не показывать как подтверждённую.
- Статус: в очереди, без реальных уведомлений.

### 4. Отдельное сообщение клиенту

- Проверить каналы, согласие и server outbox. После простоя допускать максимум одно догоняющее напоминание только для подтверждённой будущей записи; исключать прошлые, отменённые и повтор по ключу события.
- Реальные SMS/мессенджер-отправка и production SQL — только после изолированных проверок и конкретного отдельного подтверждения. Статус: в очереди, сообщений не отправляли.

Следующий шаг: согласовать сохранение этой очереди в `main` с владельцем Pro-выпуска. Для этапа 1 отдельно организовать разрешённую проверку системного выбора на Android; затем по порядку готовить этапы 2–4, не затрагивая общие Pro-файлы параллельно.
