# Eldion Pro — координация выпуска

## Цель
Принять 84 согласованных пункта на рабочем URL. Выполнено 73 из 84; осталось 11. A04/S04/X13 приняты; Source, CI и публикация не заменяют live-приёмку.

## Сделано
ROOT собрал независимый выпуск v1085: интерфейс уведомлений PR90, защита сохранности ссылок при FK-отказе удаления услуги PR55, подтверждение внешнего платёжного теста O14 и три read-only списка сегментов S10. Общий фильтр филиала требует серверного контракта; Source-пакеты с SQL остаются в очереди.

## Проверено
Причинный O14 тест воспроизводил запись production-настроек после одного ознакомления; исправление блокирует её без подтверждения внешнего теста, при пропаже review-модуля и смене конфигурации. Отключение оплаты доступно. PR55: шесть FK-определений из миграций, сохранность истории/фото, чужой владелец/ошибки и прежняя успешная очистка. Списки S10 проверены на вымышленных данных и сравнены с прежней компоновкой. Публичный URL и физическое устройство отдельно.

## Текущий этап
Кандидат на свежем main v1084; итоговые CI, интеграция, deployment и точные опубликованные ресурсы v1085 проверяются ROOT последовательно.

## Следующие шаги
Принять финальное состояние CI и публикации; затем разрешённая live-приёмка. Для серверных пакетов сначала полный protected original, actual restore, apply/read/rollback/reapply и точное сравнение.

## Зафиксированные решения
ROOT — единственный владелец shared files/выпуска; максимум два исполнителя. Полные телефоны экспорта только владельцу; списки сегментов без контактов/отправок. Внешний тест оплаты подтверждает сотрудник для текущих настроек; внутренний sandbox не является внешним тестом. Срок X07 задаёт сотрудник до начала слота. Лимит core precache не повышен.

## Ограничения и блокеры
Actual recovery 0/4; protected capture27/0 и target14/0 сохранены. Ограниченная own-cron проба завершена и не разрешает паузу рабочих заданий или новую копию. Browser refusal не обходится. SQL O08/O19/O24/расходов/сертификатов/предложений и других серверных кандидатов не применяется до закрытия своих обязательных gates. Оригинальный первый отказ удаления услуги не восстановлен; PR55 доказывает описанный FK-сценарий.

## Отдельный SOURCE: окно повторной записи
Цель: два согласованных пункта — выбранное компактное окно с исходной рамкой фото, действиями клиента в одной строке, явной датой/временем и без повторной цены внизу; очистка только прежней ошибки телефона после выбора полного номера. Критерий каждого: проверка поведения и оформления на рабочем URL после выпуска ROOT. Выполнено на сайте 0 из 2; осталось 2.

Локально сохранены исходные поля, рамки и расчёт услуги; настоящий normalizePhone передаёт результат точечному обработчику ошибки. Неверные номера, отказ автоматического выбора и посторонние ошибки не скрываются. SOURCE проверяется на вымышленных данных без внешних запросов и реальных записей. ROOT интегрирует общий provider.js, назначает версии и выпускает; live-приёмка и физическое устройство остаются неподтверждёнными. Клиентская карточка специалиста — отдельный макет, изменения клиентского сайта не разрешены.

Проверено: форма на 390/760/1440 в четырёх темах, поиск/смена клиента, исходная рамка, услуга/цена/длительность, выбор времени, повтор с составом и материалами, блокировка времени, исторический и гибкий режим. Отдельный существующий repeat-тест прошёл 720 комбинаций. Startup и сохранность клиентских URL проходят; общий лимит кеша не повышен. Следующий шаг — точный SOURCE и проверка композиции у ROOT, затем выпуск и рабочая приёмка двух пунктов.
