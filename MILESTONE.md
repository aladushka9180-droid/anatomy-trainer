# Eldion Pro — координация выпуска

## Цель
Принять 84 согласованных пункта на рабочем URL. Выполнено 73 из 84; осталось 11. A04/S04/X13 приняты; Source, CI и публикация не заменяют live-приёмку.

## Сделано
ROOT собрал независимый выпуск v1085: интерфейс уведомлений PR90, защита сохранности ссылок при FK-отказе удаления услуги PR55, подтверждение внешнего платёжного теста O14 и три read-only списка сегментов S10. Общий фильтр филиала требует серверного контракта; Source-пакеты с SQL остаются в очереди.

## Проверено
Причинный O14 тест воспроизводил запись production-настроек после одного ознакомления; исправление блокирует её без подтверждения внешнего теста, при пропаже review-модуля и смене конфигурации. Отключение оплаты доступно. PR55: шесть FK-определений из миграций, сохранность истории/фото, чужой владелец/ошибки и прежняя успешная очистка. Списки S10 проверены на вымышленных данных и сравнены с прежней компоновкой. Публичный URL и физическое устройство отдельно.

## Текущий этап
Кандидат на свежем main v1084; итоговые CI, интеграция, deployment и точные опубликованные ресурсы v1085 проверяются ROOT последовательно.

## Следующие шаги
Принять финальное состояние CI и публикации; затем разрешённая live-приёмка. Для серверных пакетов сначала полный protected original, actual restore, apply/read/rollback/reapply и точное сравнение.

## Зафиксированные решения
ROOT — единственный владелец shared files/выпуска; максимум два исполнителя. Полные телефоны экспорта только владельцу; списки сегментов без контактов/отправок. Внешний тест оплаты подтверждает сотрудник для текущих настроек; внутренний sandbox не является внешним тестом. Срок X07 задаёт сотрудник до начала слота. Лимит core precache не повышен.

## Ограничения и блокеры
Actual recovery 0/4; protected capture27/0 и target14/0 сохранены. Ограниченная own-cron проба завершена и не разрешает паузу рабочих заданий или новую копию. Browser refusal не обходится. SQL O08/O19/O24/расходов/сертификатов/предложений и других серверных кандидатов не применяется до закрытия своих обязательных gates. Оригинальный первый отказ удаления услуги не восстановлен; PR55 доказывает описанный FK-сценарий.

## Отдельный SOURCE: карточка записи
Цель: выбранная карточка с исходной золотой рамкой без квадратной подложки, одним основным повтором и тремя равными второстепенными действиями. Критерий — оформление, сохранность данных и действий на рабочем URL после выпуска ROOT. Выполнено на сайте 0 из 1; осталось 1. Приостановленная прежняя Goal уведомлений не изменялась.

Сделано: изолированы только presentation JS/CSS; исходные узлы действий, dataset и золотые рамки сохранены. Подложка очищается только у рамки, резервный аватар сохраняется. Нет изменений provider.js, версий, SQL и реальных действий. Проверено: 360/390/760/1440, четыре темы, первый визит/confirmed/planned/нулевая оплата/локальная синхронизация/отсутствующий телефон, fake callbacks всех действий и исходные формы; ближайший минимальный sheet-тест 720 комбинаций, startup/redirect проходят.

Первый SOURCE передан ROOT и прошёл 13 CI-проверок, но пользователь при ручном просмотре нашёл несоответствие выбранному изображению: плотная заливка и тёмный текст основной кнопки, чрезмерно компактная типографика. Первый SOURCE не считать готовым к выпуску. Свежий main по двум целевым JS/CSS совпадает с исходной базой: конфликтов для этой правки нет. Опубликованные JS/CSS пока не содержат нового оформления; исходный визуальный UI-гейт независим от R4/full-copy.

Коррекция R2 возвращает пропорции выбранного образца, светлую плоскую розовую кнопку с розовыми текстом/иконкой, увеличенную и выровненную исходную рамку, один ряд трёх второстепенных действий без разрыва «Позвонить». Общая розовая палитра больше не перебивает только эту кнопку; остальные темы сохранены. JS, данные, обработчики и ресурсы рамки не менялись. Локальный просмотр теперь открывает мобильный контейнер 390px на вымышленных данных; CSP запрещает внешние подключения и формы, callbacks остаются тестовыми. Прежнее подтверждение геометрии не принимать за согласование исправленного вида или рабочего сайта.

Следующий шаг: передать точный R2 в ROOT, принять допустимое визуальное свидетельство, актуализировать композицию/версии у одного владельца, выпустить и проверить целевой экран/PWA. Клиентский блок услуги отдельно уже принят на рабочем сайте клиентским владельцем выпуска; его не менять.
