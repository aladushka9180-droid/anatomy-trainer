# Цель

Добавить отдельный атомарный public RPC для 2–6 разных услуг одного подключённого мастера и локации. Каждый элемент должен стать обычной `bookings`-записью, видимой в PrimeTime Pro.

# Сделано

- Создана изолированная ветка от актуального `origin/main`.
- Подтверждено, что `book_minuta_appointment_v2` создаёт авторитетную обычную запись и может быть безопасно переиспользован в одной PostgreSQL-транзакции.

- Актуальный `origin/main`: `1a89bd11`.
- На `origin/main` нет public multi-service RPC; v85 остаётся provider-only и только для повторов одной услуги.
- Локальная static-проверка v167: 4/4; YAML release-workflow разбирается без ошибок, `git diff --check` проходит.
- Первый isolated test-gate без записей остановился на неподдерживаемом `jsonb_object_length`; проверка заменена на совместимый `jsonb_object_keys`.
- Второй isolated gate успешно создал и идемпотентно восстановил две обычные записи; дальше остановился только из-за прав тестовой temp-таблицы после `set role anon`; тестовому анонимному ролю добавлено точное `SELECT` на эту temp-таблицу.
- Третий isolated gate прошёл весь транзакционный integration-набор и остановился на подборе fixture для отдельной concurrent-проверки; подбор привязан к реально доступному тестовому мастеру, а маршрут больше не требует ровно 30-минутную сетку.
