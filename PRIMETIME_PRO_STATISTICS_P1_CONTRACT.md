## S01 — предлагаемый узкий экран

Для трёх счётчиков «Клиенты за период» сделать нативные кнопки «Посетило», «Новые», «Постоянные». Клик открывает read-only диалог со списком имён, датой первого/последнего визита в выбранном периоде и количеством завершённых визитов. Показать явные даты периода, сотрудника, источник «свои/демо» и число людей. По умолчанию телефон скрыт; из диалога нет отправки сообщения, изменения клиента или массового действия. Пустой список и незавершённая/ошибочная загрузка имеют отдельные состояния, ошибку нельзя показывать как ноль.

Строить состав из того же `reportBookings(reportRange())` и того же `reportCompletedItems`, что и счётчики. Повторить ключ `reportClientIdentity`: аккаунт, иначе нормализованный телефон. Классификация «новые/постоянные» должна использовать ту же историю до начала периода и `client_had_previous`, что `reportClientMetrics`; список должен в точности сходиться с числом. Не запрашивать новую коллекцию клиентов и не расширять серверные права. При смене периода, сотрудника, организации, источника, сессии или статуса scoped-загрузки закрывать/инвалидировать список; нельзя показывать данные предыдущего scope. Не сохранять людей в localStorage, URL или аналитике.

Пять карточек «Клиенты после перерыва» остаются вне этого P1: их источник — отдельный `get_minuta_retention_workspace`, доступный только owner/admin; он не привязан к периоду статистики. Смешивание этого набора с периодными счётчиками даст ложный scope. Отдельный drill-down для них возможен позже с явной пометкой «за всё время».

## S04 — review экспорта

Перед выбором формата показывать видимый scope: точные даты `reportRange()`, имя сотрудника или «Вся команда»/«Личная статистика», свою организацию или демо, и режим телефонов. При нажатии формата открыть отдельный review с тем же scope и названием формата. Скачивание происходит только после кнопки «Скачать»; «Отмена» не создаёт файл. Для режима «Показывать полностью» в review требуется отдельный пустой по умолчанию checkbox с прямым текстом о полных телефонах клиентов. При закрытии или смене scope checkbox сбрасывается. Если scoped-загрузка не завершилась успешно, экспорт заблокирован; scope сверяется повторно перед скачиванием, чтобы не выгрузить другой срез.

**Граница прав:** текущий UI предлагает полные телефоны всем пользователям, которым доступен экспорт, а маскирование в `reportExportPhone` — клиентское преобразование. Новый checkbox даёт осознанное подтверждение, но не является ролевым ограничением. Кандидат сохраняет текущие серверные права, не вводит новую роль и не выполняет рабочую выгрузку ПДн. Изменение политики полного телефона требует отдельного серверного контракта.

## Точки подключения для владельца общих файлов

1. В `provider.html` загрузить новый CSS после остальных provider-стилей и новый JS до `provider.js` с согласованной версией PWA. Добавить оба ресурса в применимые SW/asset контракты.
2. В `provider.js` создать контроллер один раз после объявления функций статистики: `MinutaStatisticsAuditUI.create({ document, getScope, getSegments, download })`; вызвать `mount()` после привязки DOM. `getScope()` возвращает `{ session:sessionGeneration, organization:reportOrganizationId(), organizationName:reportOrganization()?.display_name || reportOrganization()?.name || '', source:reportDataSource, start:reportRange().start, end:reportRange().end, performer:reportPerformerFilter, performerName:reportPerformerName(), status:reportUsesScopedBookings() ? reportScopedBookingsState.status : 'ready' }`. Поле имени организации сверить с фактической моделью. `download(format, privacy)` вызывает существующую функцию XLSX/CSV/PDF по формату.
3. `getSegments()` возвращает `MinutaStatisticsAuditUI.buildClientSegments({ completed:reportCompletedItems(reportBookings(reportRange())), history, identityFor:reportClientIdentity })`. Для `history` повторить источник `reportClientMetrics`: scoped rows при ready или `allBookings`, плюс отфильтрованный по организации `importedBookingHistory` (не в демо), взять даты строго раньше `reportRange().start`, исключить schedule blocks и пропустить через `reportCompletedItems`. Не фильтровать прошлое по выбранному сотруднику: действующий счётчик определяет нового клиента относительно всей организации. Проверить, что три длины совпадают с `reportClientMetrics` на одинаковом scope.
4. Удалить прежние listeners `#exportBookings`, `[data-close-report-export]`, `[data-report-export]`, которые мгновенно скачивают файл: их ставит модуль. Модуль дополнительно перехватывает клик на capture-фазе, если старый обработчик остался, но удаление устраняет параллельный путь. В конце `renderAnalytics()` вызвать `statisticsAuditUI?.refresh()` для закрытия диалога при смене scope. Модуль перехватывает невалидный submit `#reportCustomPeriod` на capture-фазе до старого общего уведомления; валидный submit остаётся прежним.
5. Для P2 убрать `setReportFiltersExpanded(false)` после выбора периода и сотрудника. Существующее закрытие при смене «Мои данные/Демо» оставить: меняется источник. Модуль добавляет подсказку тепловой карты и inline-ошибку; CSS увеличивает мобильные цели и делает карту прокручиваемой на узком телефоне с закреплённым временем.

Не оставлять старый прямой обработчик экспорта параллельно с модулем: иначе review можно обойти обычным кликом. Поскольку JS браузера не является границей авторизации, серверную политику прав подтверждают отдельно.

## Проверка при интеграции

- S01: изолированные наборы с одним аккаунтом/телефоном, повторными визитами, импортом, сменой периода и сотрудника; количество в списке равно счётчику; owner/admin и личный scope; ни одного write/RPC сообщения. Реальные контакты не выгружать.
- S04: изолированно три формата и три режима телефонов; отмена и scope mismatch не создают Blob/скачивание; полный телефон требует нового подтверждения при каждом открытии. Проверить, что скачанный тестовый срез равен указанному в review.
- Оба экрана: одинаковая тема/состояние до и после, ширины 390/760/1440, клавиатура/focus, контраст и переполнение, затем обязательный UI/PWA цикл владельца выпуска. Живые ПДн и установленная Android PWA не следуют из этих локальных тестов.
