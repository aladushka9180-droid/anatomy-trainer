# Исправления абонементов: пакет для владельца выпуска

## Цель

Три пункта принимаются отдельно на рабочем сайте после применения серверной части и обновления клиента. Локальный кандидат: 3 из 3; live-приёмка: 0 из 3, осталось 3.

| Пункт | Критерий приёмки |
| --- | --- |
| B01 | Сертификат 1000 ₽, запись 300 ₽: ручные 800 ₽ отклонены до изменения остатка и журнала; 100/300 ₽ и автоматическая сумма работают; понятная ошибка в форме. |
| B02 | Выданный абонемент → резерв → погашение → отмена продукта → разрешённый владельцу возврат: остаток возвращён один раз, статус остаётся `cancelled`. Проверить также сертификат и пакет. |
| B03 | Выдача, резерв сотрудником/публичный резерв, возврат и список используют дату основной активной локации организации; последняя дата включительна; одинаковая дата в интерфейсе и RPC. |

## Сделано

- Сервер: `supabase/migrations/20261015000127_benefit_correctness.sql`, создана через Supabase CLI. Меняет только пять существующих определений; нет DML, новых RPC, таблиц, прав или изменений старых сумм. Сохраняет отмену и ограничивает сумму ценой записи; использует существующий `get_minuta_benefit_timezone_v150`.
- Клиент: `benefit-management.js` читает `business_date`/`timezone` из рабочего списка и показывает отдельную ошибку превышения стоимости. Для прежнего сервера сохранён прежний календарь. Дата — снимок последней загрузки; сервер повторно проверяет её при записи.
- Откат: `recovery/rollback-benefit-correctness.sql`. Обе стороны проверяют точные определения до изменения всех функций, повторный запуск допустим. При иной версии остановиться и пересобрать пакет с новым владельцем определений; не обходить guard.
- Изолированные тесты и отдельный CI PostgreSQL. Fixture содержит определения функций и синтетические зависимости, без рабочих строк. Это не полный restore проекта.

## Проверено

- Native PostgreSQL 17.6: 30 сценариев, включая воспроизведение всех трёх дефектов до миграции; после неё ограничения суммы, отмена всех трёх типов, несовпадающие календари сессии/организации, публичный резерв, роли, конкуренция, повторы, исторический резерв 800 ₽, apply → rollback → reapply, повторные запуски, сохранность строк/ACL/owner/security properties и отказ при более новом определении.
- 40 тестов выдачи, подключения и дат, контроллер с русским сообщением ошибки, соседние contracts и обязательный `client-url-redirect-test.mjs`.
- Один дополнительный старый `tests/benefit-lifecycle-v150-static-test.mjs` падает и на исходном дереве: требует равенства независимых версий CSS 1036 и общего cache 1085. Основной lifecycle contract проходит. Это не исправлялось в данном пакете.
- Перед передачей read-only сверка пяти production-определений совпала с исходными guards. Production SQL и рабочие данные не изменялись.

## Текущий этап

Кандидат в `codex/benefits-correctness-20261015`; ожидает CI и приёмки единственным владельцем выпуска. Shared `provider.html`, `sw.js`, версии lazy/PWA не менялись.

## Следующие шаги

1. Владелец сверяет свежий `main`, уникальность timestamp и guards на точной интеграционной БД. Сначала полный protected backup/actual restore, затем apply/read/rollback/reapply/exact comparison с Auth/Storage/roles/ACL по проектному регламенту.
2. После допуска применить серверную часть, затем интегрировать клиент. Владелец назначает общую версию изменённого lazy-ресурса/PWA и выполняет release gates. Новая серверная часть совместима с прежним клиентом; новый клиент сохраняет fallback для старой БД.
3. На разрешённых тестовых данных выполнить три критерия таблицы через авторизованный браузер на рабочем URL; подтвердить обновление кэша. Не проводить реальные продажи, возвраты денег или отправки в рамках проверки.

## Зафиксированные решения

Выпуск и production-БД принадлежат текущему владельцу выпуска проекта. Пакет не исправляет задним числом исторические списания и не меняет денежный возврат продаж; возврат баланса продукта — отдельный от оплаты сценарий.

## Ограничения и блокеры

Полный protected restore и production-допуск для этого пакета пока не подтверждены. Авторизованный Browser недоступен в этой сессии. Локальный PostgreSQL и VM-контроллер не являются live-приёмкой. Поэтому на сайте выполнено 0 из 3; осталось 3.
