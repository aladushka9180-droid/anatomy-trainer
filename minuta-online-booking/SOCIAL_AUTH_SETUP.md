# Вход через Telegram, VK ID и Яндекс ID

Фронтенд использует три Custom OAuth/OIDC-провайдера Supabase:

- `custom:telegram`;
- `custom:vk`;
- `custom:yandex`.

Секреты провайдеров нельзя добавлять в `config.js`, GitHub Pages или репозиторий. Они хранятся только в настройках Supabase Auth.

## Общий порядок

1. Зарегистрировать отдельное веб-приложение у Telegram, VK ID и Яндекс ID.
2. В Supabase открыть Authentication → Sign In / Providers → Custom Providers и создать провайдер с указанным выше идентификатором.
3. Скопировать Callback URL, который покажет Supabase, в список разрешённых Redirect URI внешнего приложения. Для текущего проекта это адрес вида `https://cawexmmrqjvothcbgjxr.supabase.co/auth/v1/callback` — перед сохранением сверить его с Dashboard.
4. В Supabase URL Configuration добавить разрешённые возвраты:
   - `https://aladushka9180-droid.github.io/anatomy-trainer/minuta-online-booking/provider.html`;
   - `https://aladushka9180-droid.github.io/anatomy-trainer/minuta-online-booking/my-bookings.html`.
5. Для Telegram использовать OIDC auto-discovery с issuer `https://oauth.telegram.org`; Client ID и Client Secret выдаёт BotFather после настройки Login Widget и Allowed URLs.
6. Для VK ID и Яндекс ID использовать актуальные OAuth/OIDC endpoints из кабинета зарегистрированного приложения. Запрашивать только идентификатор, имя и подтверждённый email, если он доступен.
7. Применить миграции `v90 → v91` только через безопасный выпуск после подтверждённой резервной копии.
8. После успешной проверки каждого провайдера отдельно изменить соответствующий флаг в `config.js` с `false` на `true`, выпустить новую версию статических ресурсов и выполнить production health-check.

## Связывание без дублей

- Исполнитель сначала входит по email и привязывает внешний аккаунт в «Настройки → Способы входа». После этого этот же внешний аккаунт открывает существующий кабинет.
- Клиент при первом внешнем входе подтверждает существующий клиентский профиль телефоном и личным кодом. Последующие входы открывают записи сразу.
- Если внешний аккаунт или клиентский профиль уже связан с другим пользователем, сервер возвращает конфликт и ничего не перепривязывает.
- Email/пароль, личный код и отключённый SMS-вход остаются запасными способами и не удаляются.

До настройки внешних приложений кнопки видны как «Не подключён» и не выполняют перенаправление.
