# График команды — нативный UI-кандидат

Статус: подготовлен и проверен локально; не опубликован. Единственный владелец интеграции provider/HTML/SW и выпуска — «КААРДИНАТОР». Пользователь прямо попросил внедрение на сайт.

## Состав и границы

- `team-schedule-ui.js` и CSS преобразуют штатный `#shiftsPanel`: календарь, фильтры, семь дней на мобильном экране, иконки, формы в доступном dialog, свёрнутые списки/замена/аудит.
- `shift-management.js`: необязательные вызовы presentation; запуск новой смены/отсутствия; новая смена и переключение организации сбрасывают private edit ID. Состояние substitution задаётся submit-кнопке, не первому custom-select trigger. Параметры RPC, правила ролей, загрузка, обработка ошибок и отмена прежние.
- `tests/team-schedule-fixture.mjs`: только вымышленные записи, production DOM/CSS/controller; connect-src none, без Supabase, секретов и реального транспорта. `--serve` слушает loopback 57231. `?ui=0` показывает исходный вид; `?role=specialist`, `?role=admin&theme=noir-rose`, `?empty=1` — дополнительные состояния.
- `tests/shift-presentation-controller-test.mjs`: private edit identity, семидневный read, смена организации, запрет записи.

Личные рабочие часы, организация/люди, платежи, SQL, рабочие записи, Vivo и standalone прототип не меняются. Презентация не отправляет RPC и не хранит записи/комментарии: только выбранные фильтры и день в sessionStorage по actor+organization; открытый черновик сохраняется в памяти при отказе сервера и очищается при смене контекста.

## Подключение — только владельцем общих файлов

1. Сверить свежий origin/main и перенести целевой коммит. Корневой локальный MILESTONE не переносить: он относится к этой задаче.
2. В provider.html добавить CSS после темы/organization CSS и `team-schedule-ui.js` с defer до пользовательской загрузки lazy shift-management. Статический mount добавляет «Неделя» до первого RPC; штатный контроллер без презентационного файла сохраняет старое поведение.
3. Добавить обе новые UI-ресурса в OPTIONAL_ASSETS service worker. Назначить одну актуальную версию всех релизных ресурсов, обновив также регистрацию SW; повторить client-url-redirect-test на итоговом дереве до push.
4. Подключить controller contract в подходящую проверку CI. Повторить штатные v71/timeout/empty-prerequisites и визуальную проверку 390/760/1440 в итоговом дереве.
5. После публикации проверить фактически загруженные HTML/JS/CSS/SW и настоящий авторизованный раздел; безопасные взаимодействия — календарь, фильтры, открытие/закрытие форм. Рабочие записи не менять ради теста.

## Подтверждённые проверки

PASS: v71 static, shift-load-timeout-browser-test, shift-empty-prerequisites-browser-test 390/760/1440, shift-presentation-controller-test, syntax/diff-check, client-url-redirect-test на исходной версии 1065 без изменения общих ресурсов.

Через CUA с production DOM и синтетическим RPC подтверждены: новая смена с перерывом; редактирование; создание после отменённого редактирования отправляет p_shift=null; отсутствие; отмена смены/отсутствия и сохранение истории; замена сохраняет штатные RPC-параметры; отказ сохраняет специалиста/филиал/комментарий; восстановление фильтров после reload; смена организации очищает черновик; Escape возвращает фокус; мобильная пустая ячейка подставляет дату/специалиста; 30 сотрудников и длинное имя; семидневный и 31-дневный read; no body overflow 390/760/1440; светлая/Noir Rose темы; specialist имеет только собственные смены и создание, admin не включает строгий режим; сброс фильтров не снимает запрет записи.

При проверке specialist обнаружен цикл MutationObserver на уже скрытом элементе. Исправлен сравнением hidden перед записью; повторная проверка specialist в отдельном IAB прошла, штатная операция собственной смены выполнена. Старая тестовая вкладка Edge зависла и не ответила разрешённому reload/close; пользователь попросили закрыть именно её. Браузер/рабочие вкладки и телефон не завершались.

Скриншоты и CUA-результаты — локально в `outputs/team-schedule-native-proof/`; не являются live- или SQL-приёмкой.

## Оставшиеся решения / блокеры

Серверного атомарного копирования недели в продукте нет. Кандидат не содержит кнопку, имитирующую эту операцию. Пользователю задан выбор: UI сейчас, копирование отдельно, либо выпуск вместе после безопасной серверной реализации. До ответа не публиковать уменьшенный согласованный объём по догадке. Для SQL сохраняются отдельные backup/test/rollback/production gates.

Пользователь вошёл вручную; отдельная рабочая вкладка Edge подтвердила исходный #shiftsPanel v1065, 0 смен и 14 дней, штатные Pro custom-selects и серверный workspace. Старый auth/Edge-блокер снят. Рабочие записи не менялись. Fixture дополнительно включает provider-selects: вложенный picker, выбор специалиста, фильтр и создание синтетической смены проверены; выход очищает UI, specialist не зависает. Публикация и live-приёмка нового вида ещё не подтверждены.
