# A04 v190: full public restore run contract

The same `shift-substitution-v190-full-schema-test.mjs` keeps its existing empty-schema mode. The second mode runs only **inside** an external disposable PostgreSQL 17 environment after the private wrapper has restored and compared the complete `public` schema. This repository neither obtains the backup nor attests that comparison.

## External wrapper preconditions

1. Use a new PostgreSQL 17 instance with network namespace `none` and only a process-local IPv4 loopback listener. Run Node in that same namespace. Use a fresh database named `a04-shifts-full-restore` on an explicit port from 20000–65535. No socket, forwarded port, remote host, production DSN, live data query or external notification worker is allowed.
2. Restore the full schema/data/owners/ACL/RLS/indexes. Complete the wrapper's **own** before-fixture public-data and metadata comparison. Only then add the isolated `minuta_migration_guard.target` authorization row for project ref `a04-shifts-full-restore` and a fresh, short-lived marker below. Do not set `full_restore_verified` or `network_none_verified` speculatively. The wrapper alone owns these facts.
3. Marker contract (in the disposable target only): `minuta_migration_guard.a04_full_restore_marker(run_id uuid primary key, project_ref text not null, database_name text not null, full_restore_verified boolean not null, network_none_verified boolean not null, expires_at timestamptz not null)`. Reject a preexisting marker table before creating it. Insert exactly one row for a newly generated UUID, project/database `a04-shifts-full-restore`, both booleans true, expiry shortly after the run. Never print the DSN or restored rows. Remove the marker and test authorization row in `finally`; destroy the whole disposable instance on every outcome.
4. Run the script with `MINUTA_A04_EPHEMERAL_CONFIRM=FULL_RESTORE_NETWORK_NONE`, `MINUTA_A04_RESTORE_RUN_ID=<marker UUID>`, `MINUTA_A04_RESTORE_PORT=<listener port>`, `MINUTA_TEST_PROJECT_REF=a04-shifts-full-restore`, `MINUTA_TEST_DATABASE_URL=postgresql://<local user>@127.0.0.1:<listener port>/a04-shifts-full-restore`, plus the existing migration guard variables `MINUTA_TEST_MIGRATION_CONFIRM=MIGRATE_ONLY_ISOLATED_TEST_DATABASE` and `MINUTA_PRODUCTION_PROJECT_REF` (different from test ref). Supply `MINUTA_PG_MODULE` only if the existing local `pg` resolution is unavailable. These are input names, not an instruction to read or expose secrets.
5. Invoke `node tests/shift-substitution-v190-full-schema-test.mjs` from `minuta-online-booking`. It checks URL and marker before fixture writes, then uses one outer `BEGIN` for synthetic UUID fixtures, v190 apply twice, all four block forms (including v142 mapping without flag), owner/admin/specialist, ordinary substitution, deny rollback and reapply. The final outer `ROLLBACK` must run even on failure. The wrapper rechecks restored public rows/metadata after that rollback and then destroys the instance. It must not infer an exact old read RPC from the operational rollback: that rollback retains the safe v190 workspace projection and disables substitution.

`PASS` from the Node test proves only the A04 scenario inside the attested target. The wrapper must separately establish intact original public rows, function owners, grants, RLS, indexes and no lasting fixture changes. This test neither runs the combined O08 candidate nor authorizes production apply.

For the original empty schema mode, keep `MINUTA_A04_EPHEMERAL_CONFIRM=SCHEMA_ONLY_EMPTY_DATABASE`, database/ref `a04-shifts-fixture` and the existing migration guard variables. It still rejects nonempty `bookings`, `organizations` or `auth.users`.
