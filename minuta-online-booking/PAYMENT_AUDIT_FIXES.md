# Исправления аудита «Оплата и интеграции»

## Цель и область

Исправить F01–F05 из аудита от 15 октября 2026. База кандидата — свежий `origin/main`.
Приёмка исправлений на рабочем сайте: 0 из 5. Подключение магазина, настройка
секретов, включение оплаты и реальные операции в этот пакет не входят.

| Пункт | Исправление | Проверяемый результат |
| --- | --- | --- |
| F01 | Сервер сохраняет время первого запроса возврата; Edge требует разрешение на отправку | Повтор через час использует прежнюю операцию; через 25 часов POST отсутствует, резерв и ключ сохранены |
| F02 | Workspace возвращает полный резерв, остаток и признак незавершённого возврата по каждому платежу | Старый резерв вне 50 строк истории учитывается; новый возврат недоступен до завершения предыдущего |
| F03 | Отдельные русские подписи четырёх состояний сверки | `matched`, `updated`, `pending`, `failed` читаются понятно; неизвестное состояние не выдаётся за успешное |
| F04 | После любого ответа сохранения перечитывается серверное состояние; идентификатор и введённый ID сохраняются при неопределённости | Потерянный ответ обоих провайдеров восстанавливается; безопасный повтор не создаёт вторую строку; смена контекста исключает устаревшее уведомление |
| F05 | Совпадающая подтверждённая попытка распознаётся до запрета новой оплаты | Исходный запрос после webhook возвращает успех без обращения к провайдеру; чужой токен, новая операция, другая сумма или среда запрещены |

## Проверка

`payment-audit-native-test.mjs` выполняет реальные SQL-функции и миграцию,
реальные Edge-модули и контроллеры в PostgreSQL 17.6 и Chromium. Базовые таблицы,
Auth и HTTP провайдера явно синтетические. Нативная проверка включает
apply/read/rollback/reapply, сохранность строк и ACL; она не доказывает восстановление
полной рабочей базы, Supabase Auth/REST/RLS или внешний платёж.

Запуск возможен только с `PAYMENT_AUDIT_ISOLATED_FIXTURE=true`, loopback URL,
именем пустой БД `payment_audit_fixes` либо `payment_audit_fixes_<суффикс>`.
На заполненной БД скрипт прекращает работу. `MINUTA_PG_MODULE` и
`MINUTA_PLAYWRIGHT_MODULE` могут указывать на подготовленные зависимости.
Отчёт сохраняется при заданном `PAYMENT_AUDIT_OUTPUT_DIR`.

```text
node --test minuta-online-booking/tests/payment-edge-integration-test.mjs minuta-online-booking/tests/refund-amount-ux-test.mjs minuta-online-booking/tests/refund-context-recovery-test.mjs
node minuta-online-booking/tests/payment-audit-native-test.mjs
```

Повторяемый изолированный CI задан в `minuta-payment-audit-fixes.yml`. Платёжные
ключи в нём вымышленные; Edge-транспорт и браузер не допускают внешние операции.

## Совместимость и выпуск

1. Единственный владелец выпуска сверяет свежий main и кандидат, затем проводит
   обязательную квалификацию полного защищённого оригинала и восстановления.
   Синтетический тест выше не заменяет эти проектные ворота.
2. Через допущенный DB-контур применяется созданная Supabase CLI миграция
   `supabase/migrations/20261014232422_payment_audit_fixes.sql`; проверяются
   apply/read/rollback/reapply, ACL и точный состав выпуска.
3. Обновлённый обработчик возврата применяется только в отдельно разрешённой
   среде. Пакет не инициирует его production-деплой или подключение магазина.
4. Владелец выпуска интегрирует UI, назначает согласованные версии ресурсов/PWA,
   выполняет итоговые CI, публикует и проводит разрешённую live-приёмку.

Новая SQL-подготовка возвращает `dispatch_required` для неизвестного возврата:
старый Edge останавливается до POST. Новый Edge с прежней БД останавливается
на отсутствующем RPC отправки. Новый UI с прежним workspace не вычисляет остаток
по обрезанной истории и закрывает новые возвраты до получения полного контракта.
Старый UI игнорирует дополнительные поля workspace. Контроллер интеграций
сохраняет прежние `testing`, `enabled=false` и скрытое состояние незавершённых
внешних коннекторов; подтверждение внешнего теста оплаты не изменено.

По [документации ЮKassa](https://yookassa.ru/developers/using-api/interaction-format#idempotence)
защита от повторного выполнения ограничена 24 часами. Сервер закрывает POST
через 23 часа 55 минут, оставляя запас для исполнения и сети; Edge дополнительно
проверяет запас на таймаут 15 секунд. Для старых неизвестных резервов используется
консервативная нижняя граница `created_at`. Истёкшая операция требует сверки,
сохраняет резерв и не получает новый ключ автоматически.

Откат: сначала выключить предоплату и вывести новый обработчик возврата из
обращения, затем применить `supabase/rollback/payment_audit_fixes.sql` в допущенном
контуре. SQL отказывается работать при включённой оплате, восстанавливает исходные
тела трёх функций и сохраняет колонку времени отправки и финансовую историю.
Перед последующим включением оплаты требуется повторно установить исправления
и пройти внешнюю проверку тестового магазина.

## Остаток

Пакет требует интеграции владельцем выпуска и закрытия DB-ворот.
Аутентифицированный просмотр рабочего экрана и внешний платёж/возврат/чек
не подтверждены. Отсутствие подключённых функций при выключенных платежах
соответствует текущему этапу продукта.
