# Изолированный стенд серии

Подготовлен отдельный переносимый запуск PostgreSQL 17.6, без установки сервера на пользовательский ПК. Общие файлы кабинета, номера миграций и рабочая база этим пакетом не меняются.

## Два отдельных результата

`--canary` проверяет настоящий PostgreSQL17.6, Node/обычный pg-клиент внутри образа, привязку копий файлов по SHA256, откат синтетической транзакции, ожидаемый SQL-отказ и удаление собственного контейнера. Это проверка механики стенда; `fullSeriesGatePassed` остаётся false.

Полный режим восстанавливает заранее квалифицированную пустую SQL-схему и запускает исходный `repeat-series-full-schema-test.mjs`, сохранённый без изменения assertions. Требуются реальные booking/repeat/availability/shift функции, `auth.uid`, роли и включённые booking-триггеры. Все таблицы auth/public должны быть пусты. Новый API применяется только к этому созданному контейнеру; проверяются состав/материалы, отказ на третьем визите без частичных строк, повторы, длительность, пять настоящих конкурентных сценариев с ожиданием Lock, общий ресурс разных мастеров, права и rollback/reapply.

Схема-only источник должен быть отдельно разрешён и проверен владельцем контура. Хеш источника обязателен; top-level операции с данными, psql-команды, внешние серверы, пароли ролей и смена строкового режима отклоняются до создания стенда. Файл не публикуется и не входит в этот репозиторий. Полный источник нельзя восстановить из одних миграций: начальные определения таблиц в репозитории отсутствуют. Подстановка сокращённого SQL, auth-функций или нижних booking-зависимостей не закрывает полный gate.

## Запуск в разрешённом Linux-контуре

Сначала `npm ci --ignore-scripts --no-audit --no-fund` в `minuta-online-booking/scripts/series-native-runtime`. Затем:

```sh
node minuta-online-booking/scripts/series-isolated-native.mjs --canary --receipt /private-output/engine.json
node minuta-online-booking/scripts/series-isolated-native.mjs --schema /private-input/qualified-empty-schema.sql --schema-sha256 EXPECTED_SHA256 --receipt /private-output/series.json
```

Полный режим не выгружает источник и не читает production URL. Схема передаётся владельцем из предусмотренного защищённого контура. Публичный CI запускает только source-free canary; полная схема туда не подставляется. Private CI/оператор могут вызвать тот же runner после приёмки входного пакета, не меняя worker/main и не запуская новую production-выгрузку автоматически.

## Изоляция и приёмка

- Неизменяемый digest Supabase PostgreSQL17.6; сеть none, без опубликованных портов и host/volume mounts; root filesystem read-only, пользователь postgres, cap-drop ALL, no-new-privileges, ограниченные память/CPU/PID, данные только в private tmpfs.
- Новые случайные имя и ownership-label; удаляется только совпавший container ID. Недоступность Docker не принимается за подтверждение удаления; повторная проверка должна установить отсутствие точного объекта.
- Чистая временная Docker-конфигурация; Node получает через `env -i` только loopback URL и test guard. Пакет pg фиксируется lockfile; Node/library closure и входные файлы проверяются внутри контейнера по SHA256.
- Удаление контейнера, повторное восстановление очистки и удаление временных локальных файлов выполняются и после ошибки. Акт содержит только режим, hashes, статусы и класс отказа, без исходной схемы и строк данных.
- `fullSeriesGatePassed=true` требует полного теста; canary, синтаксис и unit-tests этот флаг не устанавливают. Результат не является подтверждением полного actual production/Auth/Storage restore, допуска production SQL или внедрения UI.

После полного PASS владелец выпуска отдельно сверяет actual-схему, свежую копию/restore, конкретную миграцию и разрешение, совместимость текущего кабинета, CI/Pages и живой экран. Счёт исходного внедрения остаётся 0/4 до целевой приёмки.
