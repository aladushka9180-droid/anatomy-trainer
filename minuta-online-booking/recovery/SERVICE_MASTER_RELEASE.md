# Единое добавление услуг — кандидат

## Область
Одна кнопка «Добавить услугу» открывает существующий мастер. Поиск профессии учитывает синонимы и ё/е; выбор сохраняется при фильтрации. «Своя услуга» доступна сразу, в этом же окне, с исходным узлом формы: фото, описание, особенности, ограничения, короткое название и поминутная оплата сохранены. Шаблоны допускают произвольную целую длительность 5–480 минут; собственная поминутная услуга — через исходную форму. Цены не предзаполняются. Редактирование, прайс и существующие услуги не меняются.

## Источники и пределы
Названия сформулированы самостоятельно; это стартовые типы услуг, а не копия чужого прайса. Время — редактируемая исходная оценка, без обещаний лечения. Выборочное исследование публичных прайсов передано из пользовательской координирующей сессии: [массаж](https://dikidi.net/ru/profile/bolshie_tyoplye_ruki_388521/services), [салон](https://dikidi.net/ru/profile/beauty_barbie_ulordzhonikidze_59_360649/services), [груминг](https://dikidi.net/ru/profile/prajd_grum_1295434/services). Самостоятельно проверен [официальный пример YCLIENTS для шиномонтажа и автомойки](https://support.yclients.ru/5-31-610--vnedrenie-nastrojki-zhurnala-zapisi-avto-i-shinomontazh/). Остальные наборы — редакторские предложения, не выгрузка DIKIDI/YCLIENTS; количеств чужих карточек не копировали.

## Серверная совместимость
Сначала supabase-service-catalog-v2.sql, затем UI. Каталог v1 не удаляется и не меняется. Только точная известная версия тела RPC допускает два изменения: старый клиент удаляет лишь известные своей версии профессии; результат возвращает фактически сохранённый выбор. Входная валидация, идентичность владельца, права, RLS, idempotency и лимиты прежние. Иная версия тела или коллизия catalog_version=2 останавливают транзакцию.

Откат: вернуть прежний UI, затем supabase-service-catalog-v2-rollback.sql деактивирует только v2. Строки каталога, услуги, выбранные профессии и журнал запросов остаются. Совместимость RPC сохраняется для старых PWA. Дополнительный compatibility-rollback допустим только если ни у кого нет профессий вне v1; защитный отказ нельзя обходить удалением выбора. Повторное применение активирует те же данные.

## Проверки и выпуск
PGlite PostgreSQL17: apply/reapply, v1 после v2 на том же владельце, returned/state selections, replay, anon/wrong-version/wrong-profession guards, точное изменение тела без ACL/RLS drift, rollback/reapply, сохранение пользовательских строк, полный rollback до новых выборов и отказ после них, коллизия версии. Native PostgreSQL17 выполняется отдельным CI без секретов и production. Браузерные тесты локальны и синтетические; не являются live-приёмкой.

Выпуск только владельцем Pro после свежего main v1043, назначения согласованных resource/SW версий, обязательного client-url-redirect и CI. Исправление 42501 — отдельный PR #16; без него прямая «Своя услуга» по-прежнему получит отказ. Production SQL требует точного допуска пользователя, свежего зашифрованного backup и успешной изолированной репетиции на восстановленной полной схеме; локальный пустой fixture её не заменяет.
