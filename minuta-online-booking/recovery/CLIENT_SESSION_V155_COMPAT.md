# Совместимость «Моих записей» с v155

Статус: исходное исправление подготовлено; браузерный CI и согласованный выпуск ожидаются.

Ветка: `codex/client-session-v155-compat`.
Основа: `68feda8c8ea6356dce5f0ffb49b5df20798e4088` (`main`, v1097).

## Подтверждённая причина

17 октября 2026 выполнено только чтение определений функций production-проекта
`cawexmmrqjvothcbgjxr`. `bootstrap_client_access`, `restore_client_session`,
`get_client_bookings_v3` и `rotate_client_access_code` соответствуют контракту v155.
Данные клиентов, токены и содержимое записей не запрашивались.

Сессия одной записи возвращает `normalized_phone = null` и не выдаёт
`manage_token` в списке записей. Прежний контроллер отклоняет восстановление
без телефона, а при ручном обходе этой проверки строит ссылку с пустым токеном.

## Состав исправления

- `my-bookings.js`: принимает явный `null` телефона при корректном ответе
  восстановления, показывает ограниченный доступ и только выданные сервером
  действия. Неполный ответ остаётся неподтверждённым.
- Ошибка прав/сети не запускает более старые RPC. Для известной ограниченной
  сессии fallback запрещён; старому серверу со старой сессией оставлен переход
  только при коде отсутствующей функции.
- Выход и смена токена очищают отображённые данные. Поздние ответы предыдущей
  сессии не могут заполнить страницу новой сессии.
- Выход потребляет ленивый PostgREST-запрос отзыва сессии: прежний вызов без
  `await` вообще не отправлялся. Локальный доступ очищается до ожидания сети.
- Адресные NoIO-проверки и расширенный браузерный тест используют искусственные
  сессии и изолированный HTTP-сервер. Исходящий трафик браузерного теста запрещён.
- Отдельный CI запускает эти проверки с настоящими HTML, SDK и контроллером на
  ширинах 390, 760 и 1440.

Серверные функции, RLS, авторизация исполнителя и база этим пакетом не меняются.

## Проверки и ограничения

До исправления воспроизведены отказ входа без телефона, fallback после ошибки
прав/сервера и применение позднего чтения после выхода. После исправления
локальный NoIO-набор проходит. Redirect/версии, phone/social static, v155 release
static и startup budget также проходят.

Локальная установка браузера недоступна: загрузчик Playwright получил
повреждённый пустой архив. Браузерный прогон передан отдельному GitHub CI;
до успешного результата его нельзя считать выполненным. Проверка production
с реальным клиентским входом не проводилась.

## Зависимость выпуска

Активный draft PR #131 (`codex/pro-all-sections-bugfixes-20261017-r1`) меняет
общие `my-bookings.html`, `sw.js`, `site-update.js` и версии ресурсов. Эти файлы
в данном исходном пакете намеренно не правятся параллельно с их владельцем.

Единственный владелец выпуска должен:

1. Сверить свежий `origin/main`, состояние #131 и CI данного точного SHA.
2. Интегрировать исправление отдельным коммитом в согласованный состав.
3. Назначить версию `my-bookings.js` в итоговом `my-bookings.html` и согласованную
   версию PWA. Старый ресурс кешируется по URL, поэтому замена JS без смены
   загрузочного ключа не считается доставкой установленным клиентам.
4. Повторить адресные и общие проверки на итоговом дереве, включая
   `client-url-redirect-test.mjs`, затем CI и Pages.
5. Проверить опубликованный пользовательский сценарий и обновление установленной
   PWA. Зафиксировать SHA, версии и результаты; до этого статус — ожидает выпуска.

SQL-миграция и откат v155 для этого исправления не требуются. При необходимости
отката интерфейса используется отдельный revert-коммит с согласованными версиями.
