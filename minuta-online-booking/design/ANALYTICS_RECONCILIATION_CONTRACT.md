# Согласование аналитики — кандидат правил

Основа проверки: e3642db8 (v455). Пока только тесты, runtime не изменён.

## Подтверждённые расхождения

- Демо включает реальные импортированные визиты из выбранного периода.
- Отменённая запись со старым completed outcome экспортируется как состоявшаяся.
- Получено/долг в строках отменённых и запланированных записей не совпадает с итогом, который учитывает только состоявшиеся.
- Лист клиентов считает всю доступную историю, хотя итог отчёта ограничен периодом; импортированные визиты при этом отсутствуют.
- Лист сотрудников использует другой набор агрегатов, а не детализацию отчёта. Синтетический тест подтверждает отсутствие сверки, но сам по себе не доказывает неверный серверный расчёт.

## Контракт сумм, принятый после проверки схемы импорта

- Период определяется датой визита, а не датой банковской транзакции. Это отчёт по визитам, не банковский журнал.
- «Получено» — отмеченная в результате состоявшегося неотменённого визита сумма; не выдавать отметку приложения за банковское подтверждение.
- Стоимость импорта сохраняется в «Оказано услуг на» и отдельно поясняется как история без подтверждения оплаты. Не создавать по ней фиктивную выручку или долг. Сейчас экран частично объясняет смешанную сумму, а экспорт называет её только оплатой.
- Долг считается по каждому актуальному состоявшемуся визиту: max(стоимость − получено, 0). Переплата другого клиента не погашает этот долг автоматически.
- Экран/графики/CSV/XLSX/PDF используют одинаковые функции стоимости, полученной суммы и долга.
- Клиентские суммы/визиты ограничены периодом. Если сохраняются первая дата/сегмент по полной истории, это отдельные явно подписанные поля, а не увеличение периодных сумм.
- Командные суммы/визиты выводятся из тех же отфильтрованных строк. Серверная зарплата не пересчитывается; использовать только результат для актуальных пользователя, организации, периода и сотрудника, иначе «Не рассчитано».
