# Восстановление применения промокодов

Кандидат v459 поверх v457, пока не опубликован. Рабочая логика: `18f18b4c`;
независимый браузерный тест: `55b138ff`.

- Неоднозначный ответ сохраняет исходные организацию, пользователя, визит,
  нормализованный код и ключ запроса. Изменение полей не начинает новую операцию.
- Восстановление исходных полей выполняется отдельной кнопкой без RPC, в том
  числе при незаполненном обязательном поле. Повтор требует отдельного действия.
- Подтверждение проверяет форму ответа v81. Повторный ответ может не содержать
  promotion_id; историческая скидка не пересчитывается по новой цене визита.
- Кнопка восстановления сохраняет DOM-узел при blur/change: прежний кандидат
  `3921cd7e` терял первый клик. Независимый тест дал 39/40 до исправления и 40/40
  после; assertions не ослаблены.

Локальная приёмка: promo 68, booking redemption 58, manual adjustment 42 VM;
40 native browser cases. Новый CI запускает promo VM и native suite.
Максимальный положительный тест использует фиксированную скидку, а не модель
процентного integer-умножения PostgreSQL.

Границы: реестр хранится в памяти контроллера, а не переживает перезагрузку
страницы. Синтетический сервер и реальные DOM-события не подтверждают SQL/RLS,
конкуренцию соединений или работу на пользовательских данных. SQL, Edge и
реальные финансовые операции не изменялись. Перед завершением выпуска нужны
CI, публикация, проверка ресурсов и обновления PWA с точной предыдущей версии.

## Отдельный серверный разрыв

В SQL v81 из main v457 выражение `v_amount * v_promo.value / 10000.0`
умножает два integer до деления. Изолированный PGlite воспроизводит 22003:
при 100% граница 214748 ₽ проходит, 214749 ₽ падает; при 10% —
2147483/2147484 ₽. Ошибка возникает до INSERT, это отказ применения,
а не доказанное неверное списание. Повтор существующего ключа возвращается
раньше этого выражения. Production-определение функции не проверялось.
Исправление SQL требует отдельного тестируемого выпуска с обычными этапами
бекапа, тестовой миграции и отката; frontend-recovery его не устраняет.
