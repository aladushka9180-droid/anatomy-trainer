# Карточка клиента: файлы и история (v112)

В карточке клиента доступны компактные раскрывающиеся блоки «Файлы и фотографии»
и «История клиента». Предпочтения и метки свернуты по умолчанию; ближайший визит,
контакт, количество посещений и задолженность остаются наверху.

## Поведение

- Владелец/администратор один раз включает файлы и заметки для своей организации.
  Новая миграция ничего не включает и не меняет существующие визиты.
- PDF/JPG/PNG/WebP до 10 МБ; изображения перекодируются без EXIF, до 2400 px по
  длинной стороне. У файла или заметки можно выбрать конкретный визит.
- История объединяет доступные загруженные визиты, их текущие итоги оплат,
  новые заметки и файлы. Это не неизменяемый журнал каждой платёжной операции.
  Импортированные визиты видны, но пока не выбираются как связь для нового файла.
- Материалы загружаются страницами по 30 записей, есть загрузка более ранних.
- «Убрать из карточки» архивирует материал. Физические файлы сохраняются в
  закрытом хранилище; интерфейс восстановления пока отсутствует.
- Незавершённая загрузка действует 7 дней. Служебная очистка сначала помечает
  её истёкшей, затем ждёт минимум час и удаляет объект через Storage API.
  Метаданные удаляются только после подтверждения отсутствия объекта.
  При ошибке удаления запись остаётся для следующей попытки. Сохранённые
  файлы, заметки и архивные сохранённые материалы очистка не выбирает.
- При отсутствии миграции остаётся история визитов и понятный статус подключения.

## Доступ и хранение

Закрытый bucket `minuta-client-records`, непрозрачные UUID-пути, RPC с проверками
активной организации и роли, ограничение сотрудника своими клиентами/визитами.
Файлы скачиваются авторизованным Storage API, публичные ссылки не выдаются.
Материалы не записываются в localStorage, IndexedDB или service-worker кэш.
Повтор заметки или загрузки в текущей карточке использует тот же request UUID;
при переключении клиента/организации/сессии устаревшие ответы отбрасываются.
Незавершённые загрузки не отображаются до успешной проверки Storage metadata.

## Выпуск

1. Уникальность v112 проверять на свежем origin/main; v111 принадлежит листу ожидания.
2. Проверить миграцию и `client-records-v112-integration.sql` в изолированной БД,
   затем rollback/reapply. Полный Storage HTTP сценарий отдельно от SQL policy tests.
3. Выполнять production только владельцу выпуска после свежего проверенного
   бекапа и `BACKUP_VERIFIED`, по действующим SAFE_RELEASE/AGENTS требованиям.
4. После серверной миграции подключить JS/CSS и добавить оба файла в ASSETS;
   увеличить единую версию всех ресурсов на свежей основе.
5. Владелец включает функцию из карточки. Ничего не включать за все организации.
6. До включения загрузок развернуть служебный `client-record-cleanup` и проверить
   его dry-run, отказ без служебного секрета и тестовое удаление незавершённого
   синтетического файла. Настроить почасовой запуск отдельно. Наличие SQL-функций
   само по себе не запускает очистку.

Откат: `recovery/rollback-client-records-v112.sql` закрывает доступ без удаления
файлов и заметок. Повторная миграция возвращает RPC, активация остаётся ручной.
Откат также запрещает RPC служебной очистки; данные остаются на месте.

## Проверки этой реализации

`node tests/client-records-browser-test.cjs` (Playwright; при необходимости
`MINUTA_BROWSER_CHANNEL=msedge`) проверяет повтор заметки после потерянного ответа,
экранирование текста, сохранение выбранного файла при обновлении, загрузку,
сброс сессии и мобильные размеры в светлой, тёмной и Luxury темах.
SQL regression находится в `client-records-v112-integration.sql`.
PGlite-проверка на минимальной схеме не равна полному replay production-схемы.

Воспроизводимый локальный SQL runner:
`node tests/client-records-pglite-runtime-test.mjs` из каталога приложения.
Зависимость — `@electric-sql/pglite@0.5.8`. Если пакет установлен вне проекта,
`MINUTA_PGLITE_MODULE` может указывать на его `dist/index.js`.
Runner создаёт только БД в памяти и не читает строки подключения или секреты.

Workflow `Minuta CRM isolated regression` проверяет этот runner, v113/v114 и
браузерные сценарии с подставными ответами. Он не имеет production environment
или секретов и не заменяет защищённую тестовую миграцию перед выпуском.
