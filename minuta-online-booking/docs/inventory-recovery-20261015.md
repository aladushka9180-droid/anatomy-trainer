# Склад: подтверждение и восстановление операций

Кандидат устраняет три подтверждённые ошибки. На рабочем сайте ещё не принят: выполнено 0 из 3; осталось 3. Основа — свежий main от 2026-10-09. Единственный владелец интеграции и выпуска — «КААРДИНАТОР для мастеров».

## Изменения интерфейса

- W03: `document_id` перемещения принимается как UUID; ID двух проводок остаются положительными безопасными целыми числами. Неполный, чужой или неверный ответ сохраняет исходный запрос.
- W01: до stock RPC в localStorage сохраняются UUID запроса, исходные параметры и исходный RPC. Ключ разделён по backend, пользователю и организации. Перезапуск страницы/браузера восстанавливает исходный запрос без автоматической записи; пользователь может безопасно повторить его. Подтверждённая операция освобождает журнал и разрешает намеренную новую операцию того же количества.
- Неподтверждённый запрос не сбрасывается после отказа его повторного вызова. Изменённый payload, повреждённое/недоступное хранилище, ошибка очистки и отсутствие Web Locks блокируют новую stock операцию. Web Lock сериализует отправку между вкладками. Каталог и чтение склада используют прежние пути.
- Повтор уже проведённого перемещения разрешён при остатке ниже исходного количества: idempotency проверяет сервер. Новое перемещение по-прежнему проверяет предварительный остаток и требует подтверждения.
- W02 дополнительно защищён в контроллере: лишняя точность отклоняется до создания журнала/отправки. Серверная защита остальных клиентов требует отдельной миграции.

## Серверная часть

CLI создал миграцию `supabase/migrations/20261014230902_inventory_legacy_quantity_precision.sql`. Точный обратный переход лежит отдельно в `supabase/rollbacks/20261014230902_inventory_legacy_quantity_precision.sql`; он не входит в автоматическую цепочку forward миграций.

Миграция меняет только тело legacy `apply_minuta_stock_movement(uuid,uuid,uuid,text,numeric,numeric,text,uuid)`: до поиска replay и присваивания `numeric(14,3)` запрещает лишние дробные знаки, недопустимый диапазон, null и нечисловые значения. Нулевой фактический остаток остаётся допустимым. Сигнатура, OID, владелец, SECURITY DEFINER, пустой search_path, ACL, RLS и advisory locks сохраняются. Таблицы и рабочие данные не меняются.

Применение/откат ограничены 10-секундным ожиданием блокировки и проверкой точного тела. Допустимая исходная MD5 prosrc: `5f67773de5edfa7677809eb9b6dbfa60`; кандидат: `1d9febd4d7e3e83ff01caa0095acac7a`. Windows CRLF нормализуется при установке определения функции, чтобы откат сохранял исходное тело. Отказ baseline guard требует новой сверки, его нельзя отключать.

## Уточнение SOURCE F1: исходная точность

Ревью head `7be16985` выявило обход числового guard: raw `1.0000000000000001` становится `1` после Number. Новый parseQuantity до Number разбирает десятичную строку, вычисляет точный scale из числа дробных цифр, конечных нулей и целого exponent через BigInt. Непредставимое в scale3 значение возвращает NaN и блокируется до journal/RPC; underflow вроде `1e-1000` не становится нулевым пересчётом. Проверяется только активное поле, в том числе после диалога подтверждения и при frozen replay.

Обычные три знака, нулевой count, `.125` и ранее допустимые exponent формы прихода (`1e-3`, `1000e-6`) сохранены. Конечные нули (`1.23000`, `0.00000`, `3.00000`) допускаются также прежними preview/transfer проверками как то же значение. Decimal comma раньше не поддерживалась Number — прямое `1,23` по-прежнему отклоняется. Первичные preview списания/пересчёта и перемещение сохраняют формат обычной десятичной записи; неподдерживаемую точность не округляем. Hexadecimal input не является десятичной строкой/native number input и отклоняется.

F1: сначала выполнены 18 NoIO регрессий против прежнего контроллера — 8 PASS/10 FAIL, включая исходный witness, поле после confirmation и frozen replay. После правки и расширения целевого набора 26/26 новых NoIO регрессий прошли; отдельно 3/3 затронутых прежних контрольных сценария (numeric-equivalent replay, нулевой count, новый receipt) прошли. Это реальные вызовы контроллера в VM с явными DOM/RPC/storage/lock doubles, без browser/SQL/stock операций. Guarded SQL/rollback, scope/payload/RPC/request ID/WebLock сохранены exact; исторические 134 успешных тела повторно не выполнялись. Синтаксис, diff-check и обязательный client-url-redirect проходят.

## Приёмка владельцем выпуска

1. Забрать только целевые коммиты; корневой MILESTONE этой рабочей ветки является локальной передачей и не должен заменять ROOT MILESTONE. Сверить свежий main и уникальность timestamp миграции.
2. Клиентский коммит совместим с текущими RPC и может интегрироваться отдельно от SQL. Назначить общую версию HTML/SW/precache; обновить ссылку на inventory-management.js и проверить установленный PWA после выпуска. Дизайн/соседние разделы не изменять.
3. До server apply закрыть protected backup и полную same-copy restore/Auth/Storage/roles/ACL qualification; проверить точное тело, apply/read/rollback/reapply и сохранить нужные разрешения. Никаких production SQL действий этот пакет не выполнял.
4. Принять W03 и W01 на допущенном живом тестовом контуре с безопасными данными; W02 — после серверного выпуска. Отдельно проверить actual published resources и PWA update. Browser refusal не обходить.

Ограничения: localStorage должен быть доступен, браузер должен поддерживать Web Locks. Очистка данных браузера или смена устройства теряет локальный recovery journal; старые незавершённые операции без сохранённого request ID перед выпуском требуют сверки серверного журнала. Автоматически считать их выполненными или повторять новым ID нельзя. Ускорение склада, перерасчёт старых данных и исправления соседних разделов в этот пакет не включены.
