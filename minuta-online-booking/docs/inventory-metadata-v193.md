# O24: категории и иконки позиций

Область: необязательная категория (до 60 символов) и иконка из фиксированного списка. Пустая иконка означает прежний автоматический выбор. Название, артикул, остатки и нормы не используются для хранения оформления.

## Совместимость

v193 добавляет два поля с пустым значением по умолчанию. Существующий читатель сохраняет прежние поля ответа и дополнительно сообщает `item_metadata_version=193`; v130 сохраняет свои поля перемещений. Старый writer не меняется и сохраняет новые значения. Новый writer атомарно вызывает старую проверку/запись и сохраняет метаданные; при ошибке нельзя повторять запись через старый RPC, теряя выбранные значения. Замена неожиданно изменённого читателя блокируется проверкой его исходного тела. В интерфейсе новые поля скрыты, пока сервер не подтвердил поддержку.

## Проверки и допуск

1. Изолированный `tests/inventory-metadata-v193-db-test.mjs`: пустые/заполненные значения, ограничения, права, прежний writer, повтор миграции, откат с сохранением данных и повторное применение. Это не восстановление рабочей копии.
2. `tests/inventory-soft-ui-browser-test.mjs`: поля и сохранение через тестовый адаптер, старый сервер без метаданных, возврат к автоматической иконке, прежние состояния ошибки/черновика/прав на 390/760/1440.
3. После слияния SQL и сценария проверки в main: свежий штатный encrypted backup того же main SHA, затем `minuta-supabase-restore-drill.yml` с `restore_target=ephemeral`, точными `backup_run_id`, `commit_sha`, `candidate_sha` и `candidate_version=v193`. Существующие ограничения возраста копии (не более двух часов), SHA, зашифрованного архива, восстановления и контейнера без сети сохраняются.
4. Сценарий v193 работает только внутри уже восстановленного одноразового контейнера с `NetworkMode=none`. Применяет миграцию дважды, сравнивает содержимое записей, итогов визитов, товаров, остатков, норм и истории; проверяет запись/чтение выбранных значений в откатываемой транзакции; возвращает прежний reader и повторно применяет миграцию. В отчёт выходят статусы и хэши SQL, данные остаются в закрытом журнале штатного workflow.
5. Только после успешной проверки точного кандидата и отдельного подтверждения пользователя допускается production apply. В этой подготовке production SQL не выполняется. Перед apply заново проверить свежесть копии и актуальность main.
6. После apply выпустить согласованные версии UI/ресурсов и проверить создание, повторное открытие и очистку полей на рабочем сайте. Лишь затем закрыть O24.

## Откат

`supabase-migration-v193-rollback.sql` отключает новый writer и возвращает прежний reader. Новые колонки и введённые значения сохраняются. Старый UI продолжает читать и сохранять товары. Удаление колонок не входит в откат. Повтор v193 снова открывает сохранённые значения.

Текущий основной учёт: корневой MILESTONE.md; Source, CI и штатная публикация SQL-файла не являются применением миграции к базе.
