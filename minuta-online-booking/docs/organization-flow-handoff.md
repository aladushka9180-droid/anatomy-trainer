# Организация — согласованный обзор

## Цель и границы
Последний макет organization-flow.html из чата «Организация»: компактная общая карточка, один активный шаг, остальные шаги доступны для выбора, сворачивание заполненной настройки, редактирование названия и данные поддержки. Пользователь отдельно выбрал реальные редакторы в существующих разделах и честный статус вместо демонстрационного API включения записи.

Собственные файлы: organization-flow.js, organization-flow.css, tests/organization-flow-fixture.mjs, tests/organization-flow-browser-test.mjs, отдельный workflow minuta-organization-flow.yml и этот документ. Общие provider.html/provider.js/sw.js/site-update.js, organization.js и редакторы людей/филиалов не изменены. SQL, рабочие записи, настройки публичной записи и приглашения не менялись.

## Подтверждённые состояния
- Филиал: активен и имеет непустой адрес.
- Сотрудник: действующее членство с is_bookable=true. Приглашение не засчитывается.
- Услуги: get_minuta_shift_workspace возвращает активные услуги принимающих участников; у каждого есть услуга с названием и положительной продолжительностью.
- Рабочее время: у каждого принимающего участника есть действующая смена в активном филиале с адресом, корректным временем и без отсутствия на дату. Проверяем ближайшие 14 календарных дней по Europe/Samara. Это проверка заполнения, а не гарантия свободного слота, полной рабочей недели или включённой записи.
- При ошибке, таймауте, другом organization_id или недостающих массивах услуг/смен эти шаги не подтверждаются. Для специалиста полная командная проверка не утверждается: её выполняет владелец/администратор.
- public_booking_enabled читается только из workspace. Заполнение шагов не меняет флаг. Самостоятельное включение пока недоступно; интерфейс прямо объясняет это.
- Название сохраняет прежний organizationForm и RPC update_minuta_organization. Pending предотвращает повторную отправку; при отказе и последующем reload введённый текст сохраняется. Закрытие происходит только после подтверждения имени сервером.

## Подключение единственным владельцем общих файлов
1. В provider.html подключить organization-flow.css после существующих слоёв оформления и organization-flow.js (defer) до provider.js. Номер ресурсов назначает владелец выпуска на свежем main.
2. В provider.js непосредственно перед созданием organizationController добавить:

```js
const organizationFlowController = window.MinutaOrganizationFlow?.createController({
  db, notify, requireWrites,
  getCurrentUser: () => currentUser,
  getSessionGeneration: () => sessionGeneration,
  sessionIsCurrent
});
organizationFlowController?.bind();
```

В существующий onActiveOrganizationChange после получения organization добавить:

```js
organizationFlowController?.setOrganization(organization);
```

Модуль сохраняет прежние узлы/ID формы, ошибки, заголовка и данных поддержки. Соседние редакторы не переносит. Переходы используют прежние section/view buttons; заполненный филиал/сотрудник открывает существующую форму с сохранёнными значениями. Проверка загружается только при видимом обзоре и повторяется при возвращении из редактора; старый ответ другой организации/сессии игнорируется.

3. Зарегистрировать оба ресурса в OPTIONAL_ASSETS SW; не расширять core precache сверх текущего лимита. Обновить HTML/JS/SW/site-update согласованно по регламенту выпуска, выполнить redirect/startup и новый тест на итоговом объединённом дереве. Совместимость с актуальной правкой «Люди и филиалы» проверить после её интеграции.
4. Новый workflow проверяет исходный модуль с реальным organization.js и групповой навигацией на полностью изолированных synthetic данных. Подключение в целый provider, актуальный lazy loader, версии SW и живой экран отдельно проверяет интегратор.

Снимки отдельно сохранены в task visualization/implementation-qa.
