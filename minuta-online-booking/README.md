# Минута — онлайн-запись

Онлайн-запись для GitHub Pages с общей базой Supabase. Клиенты выбирают услугу и свободное время, а исполнители регистрируются, добавляют свои услуги и управляют заявками в отдельном кабинете.

Доступ к данным ограничен политиками Row Level Security: клиент не может читать чужие записи, исполнитель видит только свои услуги и заявки.

## Надёжность

- Кабинет подписывается на изменения записей, услуг, графика и исключений через Supabase Realtime и дополнительно полностью сверяется с сервером раз в минуту.
- Недавние записи, услуги и расписание сохраняются в IndexedDB не дольше 24 часов, доступны только для чтения при сбое связи и очищаются при выходе; имена и телефоны клиентов в офлайн-кэш записей не попадают.
- Изменения в кабинете разрешаются только после успешной полной синхронизации; ответы от предыдущей пользовательской сессии отбрасываются.
- Страница клиента показывает, проверена ли возможность записи, и не выдаёт сетевую ошибку за успешно созданную заявку.
- При двух и более исполнителях клиент может отфильтровать услуги по специалисту; при одном исполнителе лишний шаг автоматически скрыт.
- Owner/admin могут переключить существующий журнал в read-only командный режим и фильтровать записи по филиалу, специалисту и назначенному ресурсу; командные ПДн не пишутся в офлайн-кэш.
- В контуре v69 owner/admin настраивают кабинеты, массажные столы и оборудование по филиалам; база атомарно назначает свободные ресурсы и блокирует их двойное бронирование.
- Исполнитель может атомарно создать курс из 2–24 визитов и затем перенести или отменить одну запись, выбранную и последующие либо все будущие записи серии. Если хотя бы одно окно занято, вся операция откатывается.
- Создание записи идемпотентно: повтор после обрыва связи использует тот же UUID, возвращает первоначальный результат и не создаёт дубль.
- Клиент может открыть персональную страницу управления записью сразу после подтверждения.
- Если свободного времени нет, клиент может оставить заявку в листе ожидания и управлять ею по личной ссылке.
- На странице управления записью клиент может подтвердить визит кнопкой «Да, я приду».
- Ограничения отмены и переноса проверяются на сервере; исполнитель настраивает сроки и максимальное число переносов.
- Можно включить предоплату: клиент получает персональную платёжную ссылку, а исполнитель отмечает статус в кабинете.
- Автоматически завершённые после рабочего дня визиты отмечаются оплаченными на полную стоимость и сразу учитываются в статистике; результат можно исправить вручную.
- Для услуг длительностью 1 минута цена считается тарифом за минуту; после визита мастер указывает фактическое время и получает итоговый расчёт.
- В каждой записи можно изменить состав сеанса, добавить каталожные или произвольные услуги и сохранить историю первоначальной и итоговой стоимости без изменения каталога.
- Шаблоны уведомлений и отметки об их отправке синхронизируются между устройствами через Supabase.
- Владелец может безопасно находить клиентов после перерыва: предложение готовится только при отдельном согласии, а период защиты блокирует частые повторы.
- В кабинете есть голосовой помощник: он локально разбирает русские команды, показывает сводку расписания и открывает только предзаполненный черновик. Офлайн он использует существующую обезличенную копию не старше 7 дней, сообщает время обновления и перепроверяет свободное время после восстановления связи. Озвучивание можно остановить повторным нажатием; на мобильных устройствах поддержан Web Speech и безопасный переход к системной диктовке клавиатуры. Создание записи остаётся за защищённой формой и требует явного подтверждения пользователя.
- Service Worker использует единый номер сборки и не подменяет отсутствующие JavaScript-файлы HTML-страницей.
- Supabase SDK закреплён локально с SRI-проверкой, а CSP разрешает соединение только с используемым проектом.
- Портфолио синхронизируется между телефоном и ПК: мастер загружает фото «до» и «после», отдельно указывает число сеансов и меняет порядок перетаскиванием либо кнопками.
- Исходные изображения преобразуются в WebP без EXIF; файлы хранятся в закрытом Storage, а публикация возможна только после подтверждения согласия клиента.

Проверка перед публикацией:

```bash
node minuta-online-booking/smoke-test.mjs
```

Проверка уже опубликованного сайта и публичных RPC:

```bash
node minuta-online-booking/production-health-check.mjs
```

Миграции `v41`–`v64` являются неизменяемой историей, а v64 остаётся последним определением защищённого удаления. Слои v65–v78 последовательно добавляют организации, команду, филиалы, ресурсы, аватары, смены, зарплаты, клиентские продукты, наблюдение за публичной страницей, цвета, политики записи, защищённые Telegram-напоминания и Realtime-готовность услуг. v79–v86 аддитивно добавляют серии и пакеты записей, групповые события, лояльность, склад, безопасный возврат клиентов, взаимную исключаемость выгод и корректный порядок проверки групповых пересечений; они не заменяют защищённые RPC v61/v64/v76. Точный порядок описан в `OPERATIONS.md` и `SAFE_RELEASE.md`.

Настройка мониторинга, уведомлений, резервных копий и отдельного тестового проекта описана в `OPERATIONS.md`.

## Публикация

GitHub Pages: Settings → Pages → Build and deployment → Deploy from a branch → `main` → `/(root)` → Save.
