(`01a0f8f5-670e-7f62-a2e0-fe72554a22ca`); полный CURRENT restore — прежний

## Источники и границы доказательства

- [Статья Гном.Гуру об офлайн-режиме, 02.03.2020](https://gnom.guru/ru/Blog/BPage/2518191662820853518) заявляет запись клиента, шаблон, поздравление, сотрудника, работу с ранее загруженными данными и последующую синхронизацию между устройствами. Это заявление поставщика на дату статьи, не проверка актуального приложения или всех его функций.
- [Статья Гном.Гуру об учёте материалов, 27.03.2018](https://gnom.guru/ru/Blog/BPage/2519030557121186233) описывает материалы, нормы, списание после визита, себестоимость и остатки. Она не доказывает, что каждая из этих операций сейчас доступна без сети.
- [Страница возможностей Гном.Гуру](https://gnom.guru/ru) перечисляет историю клиентов, услуги, материалы, товары, расходы/доходы и работу с нескольких устройств. Офлайн-поведение этих отдельных разделов и физическое Android-приложение нами не проверены.
- Статусы PrimeTime ниже основаны на текущем `origin/main`, проектных проверках и `MILESTONE.md`; где нет отдельного живого сценария, указано «код есть, офлайн не подтверждён». Установленная Android PWA отдельно не проверена.

## Ворота каждого этапа

Этап 1: прежнюю локальную интеграцию с SW v999 не переносить целиком: она устарела относительно живого Pro. Текущий PR №7 содержит только независимые файлы черновиков и панели; новый экран, авторизованный сценарий и PWA ещё не подключены. Пустая копия схемы тестовой БД проверена, полный restore с данными и работа с реальным складом не выполнялись. Перед выпуском нужны свежий `origin/main`, свободная полоса владельца UI-аудита, интеграция без роста PWA-ядра, CI, живые ресурсы и безопасный экранный сценарий. Для SQL v186/v187 точные границы backup/restore/rollback указаны в `minuta-online-booking/recovery/V186_V187_OFFLINE_CATALOG_RELEASE.md`; применение только v186/v187 разрешено 02.10 после полного recovery gate.

Изолированная схема и данные → проверка конфликта, повтора и потерянного ответа → браузерные сценарии 390/760/1440 и PWA без реальных записей → свежий `origin/main` и свободная полоса единственного владельца выпуска → обязательные CI/деплой → реальные ресурсы, экран и безопасное действие на рабочем сайте. Для нового production SQL отдельно требуются точное разрешение, свежий backup, isolated restore, проверка отката и preflight. Физический Android остаётся отдельной проверкой.
