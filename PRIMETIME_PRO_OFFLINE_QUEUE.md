# PrimeTime Pro: очередь офлайн-возможностей

Владелец очереди, изменений и последовательного выпуска — задача «Гибкое время офлайн-записи — Pro и клиент». Очередь описывает применимые сценарии, а не обещает совместимость с Гном.Гуру. Выпуск UI-аудита остаётся у его отдельного владельца; пересекающиеся файлы и полосу выпуска не занимать одновременно.

## Источники и границы доказательства

- [Статья Гном.Гуру об офлайн-режиме, 02.03.2020](https://gnom.guru/ru/Blog/BPage/2518191662820853518) заявляет запись клиента, шаблон, поздравление, сотрудника, работу с ранее загруженными данными и последующую синхронизацию между устройствами. Это заявление поставщика на дату статьи, не проверка актуального приложения или всех его функций.
- [Статья Гном.Гуру об учёте материалов, 27.03.2018](https://gnom.guru/ru/Blog/BPage/2519030557121186233) описывает материалы, нормы, списание после визита, себестоимость и остатки. Она не доказывает, что каждая из этих операций сейчас доступна без сети.
- [Страница возможностей Гном.Гуру](https://gnom.guru/ru) перечисляет историю клиентов, услуги, материалы, товары, расходы/доходы и работу с нескольких устройств. Офлайн-поведение этих отдельных разделов и физическое Android-приложение нами не проверены.
- Статусы PrimeTime ниже основаны на текущем `origin/main`, проектных проверках и `MILESTONE.md`; где нет отдельного живого сценария, указано «код есть, офлайн не подтверждён». Установленная Android PWA отдельно не проверена.

## Ворота каждого этапа

Этап 1: компонент `offline-catalog-panel.js` подключён к разделу услуг только в локальной ветке; её старый SW v999 кэширует компонент и хранилище. Синтетический экран Pro 390/760/1440, офлайн-сохранение, конфликт и выдача PWA-ресурсов без сети проверены до перенумерации. Для существующей услуги онлайн читаются вместе версия и показанные поля; материал загружается только явным действием из тестового каталожного read RPC, а его поля и версия сохраняются для офлайн-правки после перезагрузки. Отсутствие снимка блокирует изменение. Кандидат не опубликован и не проверен на живом авторизованном экране; рабочий склад не читали. `origin/main` `bc745597` содержит другой v181 SQL и ограниченный release gate для складского hotfix; его production-применение не подтверждено. UI-аудит выпустил PWA v1009 и изменил общие `provider.html`, `provider.js`, `site-update.js`, `sw.js`. Каталожный SQL локально перенумерован в v182/v183; оба isolated PostgreSQL job успешны. Общий CI этой старой ветки пока не зелёный: smoke упал на startup budget, safety — на двух сценариях вне каталога. Причину проверять после интеграции со свежим main; до этого не выпускать UI/PWA. После hotfix сверить свежий `main`, перенумеровать PWA v999, перенести только целевую правку поверх общих файлов, затем обновить хеши и проверки. До этого не интегрировать пакет и не применять SQL. Полная isolated репетиция дополнительно заблокирована текущим protected workflow (поддерживает v180 и отдельный hotfix v181, но не каталог); точные границы backup/restore/rollback — в `minuta-online-booking/recovery/V182_V183_OFFLINE_CATALOG_RELEASE.md`. Production SQL остаётся отдельными воротами.

Изолированная схема и данные → проверка конфликта, повтора и потерянного ответа → браузерные сценарии 390/760/1440 и PWA без реальных записей → свежий `origin/main` и свободная полоса единственного владельца выпуска → обязательные CI/деплой → реальные ресурсы, экран и безопасное действие на рабочем сайте. Для нового production SQL отдельно требуются точное разрешение, свежий backup, isolated restore, проверка отката и preflight. Физический Android остаётся отдельной проверкой.
