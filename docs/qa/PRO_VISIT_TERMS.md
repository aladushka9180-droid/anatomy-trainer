# Индивидуальный тариф визита: локальный контракт

Модуль `minuta-online-booking/provider-visit-terms.mjs` подготавливает общий расчёт и перенос условий для согласованной функции цены минуты. Это отдельный кандидат от `68feda8c8`, не подключённый к текущим формам, service worker или опубликованному кабинету. Кандидат серверного редактирования описан в [PRO_VISIT_TERMS_SERVER_CONTRACT.md](PRO_VISIT_TERMS_SERVER_CONTRACT.md); SQL не применён к продукту. Исходные пять критериев функции остаются открытыми — **0/5**.

## Инварианты

- `calculateVisitTerms(rate, minutes)` считает только основную поминутную позицию в целых рублях: ставка 0–1 000 000, длительность 1–480, сумма позиции не выше существующего предела 1 000 000. Сумма всего сеанса, допуслуги и полученная оплата не являются ставкой. Округления и подстановки нуля для пустого ввода нет.
- `captureVisitTerms` получает настоящую выбранную поминутную услугу и явную область actor/organization/service. При отсутствии override используется её цена, нулевой override сохраняется. Собственные неизменяемые примитивы не зависят от последующей мутации каталога. `pricingMode` — только клиентский смысл снимка, не новая колонка БД и не доказательство серверной поддержки режима.
- `withVisitTermsDraft` добавляет свой `visitTerms` в существующий черновик. `restoreVisitTermsDraft` различает старый формат, повреждение и несовпадение владельца/организации/услуги. Автоматического выбора другой услуги или политики копирования тарифа нет.
- `visitTermsFingerprintCanonical` дополняет существующий canonical array валидированным кортежем. Если аргумент условий отсутствует, JSON остаётся байт-в-байт прежним. Явные `null`/повреждённые условия не отбрасываются. Модуль не очищает UNKNOWN, не создаёт request ID и не повторяет запись.
- `sameVisitTerms` сравнивает только полный локальный кортеж. Совпадение не доказывает atomic write, права, подтверждённую запись БД или согласованность primary/session revision.

## Подключение, которое остаётся выполнить

Снимать условия до первого await; затем передавать один снимок в расчёт карточки/времени/результата, черновик, frozen request и durable offline row с прежними actor/session guards. Старые UNKNOWN-попытки не сбрасывать из-за нового формата. По прямому ответу пользователя смена услуги берёт цену новой услуги. Для повтора/серии координатор выбрал копирование ставки исходного визита с возможностью явного изменения в рамках ранее разрешённого обратимого выбора; это не выдаётся за прямой ответ на второй вопрос. Переход к фиксированному режиму не должен сохранять скрытый поминутный override.

Перед активацией нужен квалифицированный единый атомарный write/readback тарифа, минут, сумм и primary/session, включая одну минуту, текущие серверные определения и действующие full-copy/restore/SQL ворота. Прежние раздельные updates в `applyPerMinuteBookingTerms` и ранний успех для одной минуты не заменяют этот контракт. Подключение к DOM и целевая визуальная проверка — последующие этапы; текущий CORE budget и версии ресурсов не изменены.

## Адресная проверка

`node --test minuta-online-booking/tests/provider-visit-terms-test.mjs`

Проверяются реальные чистые функции на синтетических значениях: целые рубли, одна минута/ноль, границы, snapshot после await/изменения каталога, JSON черновика/очереди, область, повреждение, byte-exact legacy fingerprint и изменение идентичности выбранного тарифа. Сеть, SDK, SQL, Auth/Storage, формы и рабочие данные не используются.
